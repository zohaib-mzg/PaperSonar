## Implementation decisions

1. **OpenAlex adapter** uses cursor paging (`cursor=*`, `per_page` ≤ 100) for backfill partitions and bounded re-fetch reconciliation for incremental runs (no free change feed assumed).
2. **Crossref adapter** uses fixed inclusive `from-index-date`/`until-index-date` windows with cursor paging and an overlap window on the next sync.
3. **arXiv adapter** uses OAI-PMH ListRecords with `from` only (no `until`), default `metadataPrefix=arXiv`; a daily-expired token restarts the window (idempotent upserts make this safe). Deleted tombstones are recorded (counted, not staged) per the deletion policy.
4. **DataCite adapter** uses REST cursor paging with `sort=-updated` and configurable `query` filters. The updated-range incremental query must be validated against the live API before production sync; until then sync runs are bounded reconciliation.
5. **Zenodo adapter** uses OAI-PMH `from`/`until` ListRecords with prompt page persistence; token expiry restarts the window. REST `/api/records` supports bounded backfill/detail fetches.
6. All adapters share one HTTP client with bounded exponential backoff + jitter, `Retry-After` compliance, and permanent-4xx non-retry classification.
